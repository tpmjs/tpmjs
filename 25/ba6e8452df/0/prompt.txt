# Add "Sandbox Logs" Tab to Agent Detail Page

## Context

Agents with sandbox enabled execute shell commands, read/write files, and list directories. The stdout/stderr output from these tools is stored in `Message` records (role=TOOL, toolResult JSON). Users want a dedicated tab to view these sandbox tool execution logs — showing what commands ran, what output they produced, and whether they succeeded.

## Design

Add a "sandbox logs" tab to the agent detail page (`/dashboard/agents/[id]?tab=sandbox-logs`). Only shown when `agent.sandboxEnabled === true`. Fetches sandbox-specific tool results from the existing `/api/agents/[id]/logs?type=tool_call` endpoint (enhanced to include `toolResult` data for sandbox tools). Renders each log entry with a terminal-like display for shellExec stdout/stderr.

## Files to Modify

### 1. `apps/web/src/app/api/agents/[id]/logs/route.ts`

Add a new query param `sandbox=true` that filters for sandbox tool names only (`shellExec`, `readFile`, `writeFile`, `listFiles`) and includes `toolResult` JSON in the response (currently truncated to 500 chars — for sandbox logs, return the full result).

Update the `LogEntry` interface to include:
```typescript
toolResult?: {
  // shellExec
  stdout?: string;
  stderr?: string;
  exitCode?: number;
  durationMs?: number;
  // readFile
  content?: string;
  path?: string;
  size?: number;
  // writeFile
  success?: boolean;
  bytesWritten?: number;
  // listFiles
  entries?: Array<{ name: string; type: string; size: number | null }>;
  // common
  truncated?: boolean;
};
toolInput?: Record<string, unknown>;
```

Also extract tool inputs from ASSISTANT messages' `toolCalls` JSON (match by `toolCallId`) so each log entry shows both the input (command, path) and the output (stdout, stderr).

### 2. `apps/web/src/app/dashboard/agents/[id]/page.tsx`

- Add `'sandbox-logs'` to `PageTabId` union type and `VALID_TABS` array
- Conditionally add the tab to `pageTabs` array only when `agent.sandboxEnabled` is true:
  ```typescript
  ...(sandboxEnabled ? [{ id: 'sandbox-logs' as const, label: 'Sandbox Logs' }] : []),
  ```
- Add the tab content panel that renders `<SandboxLogsPanel agentId={agent.id} />`

### 3. New: `apps/web/src/components/SandboxLogsPanel.tsx`

A client component that:
- Fetches `GET /api/agents/{agentId}/logs?sandbox=true&limit=50` on mount
- Shows a chronological list of sandbox tool executions
- Each entry is a card showing:
  - **Header**: Tool name icon + badge, conversation slug, timestamp, duration
  - **shellExec**: Command in a code block, stdout/stderr in a dark terminal-style `<pre>`, exit code badge (green for 0, red otherwise)
  - **readFile**: File path, content preview (collapsible)
  - **writeFile**: File path, bytes written, success badge
  - **listFiles**: Path, file tree entries
- "Load more" button at bottom (offset-based pagination)
- Auto-refresh toggle (poll every 5s when enabled)
- Empty state when no sandbox logs exist yet

Uses existing `@tpmjs/ui` components: `Badge`, `Button`, `Icon`, `Skeleton` (for loading state).

### The Gap

The biggest missing piece is **standardization**. As dot-ai explicitly states, it's a "temporary solution" until providers converge. There is no equivalent of `.editorconfig` for AI coding tools yet.
